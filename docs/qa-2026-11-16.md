# QA round, 16 Nov 2026: 50 agents (30 Haiku-class screen/look checks, 20 Sonnet flows)

All read-only code reviews: no agent ran the app, signed in, or touched live data. Findings marked CONFIRMED were checked by the main session in the code or the live database. Everything else needs a run check before it is called fixed.

## Checked and SAFE (live database)
- A member can only change their display name in their membership row, so nobody can move into another trip.
- The booking-documents bucket is limited to the trip's own members.
- The backup copies of real bookings and expenses can't be read by the app or users.
- Your real trip's 7 hotels are all read in the right city by the planner.
- Your real trip has 388 swipes, 282 cards, 140 places: under the 1,000-row read limit.

## Fix first: live now, affects the trip (12-31 Dec)
1. Booking import: a booking outside the trip dates is saved with no date and no warning. CONFIRMED.
2. Report box: sending a report offline, then tapping "handled", crashes the whole app (no error safety net anywhere). CONFIRMED.
3. Places: the couple filter ("ours" / "together") does nothing. CONFIRMED.
4. Offline in Japan (trains, weak eSIM):
   - no time limit on requests, so "signal but no data" freezes every save and the queue
   - the app can hang on the loading screen when the sign-in token refreshes
   - a booking or place saved offline can vanish later if the server refuses it
   - offline saves share phone storage with caches; if it fills, unsent changes are lost on close
5. Wrong "empty" screens while loading or offline: Expenses says "all settled", Plan says "nothing planned", Discover says "no places", Home says "no flight / no hotel".
6. Expenses: a repayment recorded by both people counts twice; changing the exchange rate changes old balances; the new-expense form starts in yen while the screen shows shekels.
7. Web app updates: on a slow connection the phone keeps the old version (why friends needed a full close).
8. Double taps create duplicates: checklist add, hotels import, "add to this day". Two couples ticking the same checklist item offline can erase one tick.
9. Share link: includes a couple's private places and stops.
10. Translator: no message when the connection fails, and buttons can freeze with no time limit.
11. Sign-out on a shared phone: notifications keep going to the old account; map and photo caches stay.
12. Plan: the day strip doesn't scroll to today. Rating: tapping a star before it loads wipes the saved note.
13. "Switch trip" in the menu dead-ends in the trip picker.
14. Search: Japanese text only matches at the start of a name.
15. Match pop-up: Enter or Space can press the hidden card behind it.

## Security (live, not urgent for 4 users, before opening to the public)
- Notifications: the server will send to any https address a user saves (should allow only real push services).
- Invite sign-up function: no attempt limit, and its answers reveal which invite codes are valid.
- Places can still be inserted directly (rule 3); the fix file exists but isn't applied.
- The usage-event counter can be flooded by anyone.
- The planner function returns raw database errors and has no rate limit.
- Approved user photos keep their GPS data when published.

## Before open sign-up and the App Store (after the trip)
Sign-up code (off, local): invite + Google loses the invite; Google errors silent on the web; expired confirmation has no resend; link on another device ends in a generic error; email sign-ups skip the questions.
Leave trip / delete account: not live; apply order and 15 issues in the agent report (delete is not transactional, files left behind, backups, rejoin shows twice).
First run: 8 questions before the first card; invited users can't skip them; guest import retry makes a second trip; sign-up sheet every 12 swipes; push asked after 3 likes.
Credits / trip pass: off; parked until the money model is decided.
Android test build: translator mic doesn't work; booking PDFs don't open offline; backup setting allows restoring a session.
Scale: tables over 1,000 rows are cut silently.

## Polish (any time)
Accessibility (screen reader names, focus in dialogs, headings), dark mode contrast (white tick on green), small screens (320px), large text, tap targets under 44pt, right-to-left icons, haptics, motion.
