# Toogo data map, 16 Nov 2026

What we save, where, who can see it, and what is missing before open sign-up.
Built from the repo (SQL, edge functions, app code) and the live table list the owner gave. Nothing was run on the live database. Where the repo cannot say what is live, this file says "unknown".

---

## 1. One screen

**Per person (account)**
Email, password hash, display name, questionnaire answers, credits, notification address, photo uploads, problem reports. Only you see it (the server and the owner see it too).

**Per trip (shared with the trip's members)**
Trip, members, plan, places, swipes, bookings and their files, expenses, hotels and notes, packing lists, share links. Every member of the trip sees all of it. Nobody outside the trip does.

**Shared by everyone**
The place library, cities, the guide, place photos. Any signed-in user can read it. Card photos are public files.

**App and ops data (only the owner, via the server)**
Usage events, AI call log, AI counters, settings, flags, join attempts, backups, test data.

**Three things to know today**
1. A user cannot delete their account or leave a trip in the app. The delete code is written but not applied.
2. Booking files (can hold passport numbers) are kept as uploaded, as long as the trip exists.
3. Only usage events have a deletion rule (12 months). Everything else is kept forever.

## 7. What we do NOT save (checked in code)

| Claim | Check | Result |
|---|---|---|
| Card numbers | No column, no field, no code for it. | True as a field. Free-text fields (`essentials.value`, `bookings.notes`, `expenses.title`) and uploaded files could hold one if a person types or uploads it. |
| Passport numbers | No column. The booking reader copies "numbers as written" from the document into booking fields. | **Not a field, but the original file is saved** (see below) and a number can reach `notes`. |
| Live location | No `geolocation` call in `src/`. No location permission in `Info.plist` (only camera and photos). | True. We see no GPS. Hosts see the IP address, we do not store it. |
| Contacts | No contacts permission or code. | True. |
| Google or Apple tokens | No table of ours holds a token. Apple sign-in is refused by the sign-up trigger. | True for our tables. Supabase keeps the Google profile (id, email, name, photo) in its own auth tables. Not checked. |
| Passwords | `sign-up` function passes the password to Supabase Auth, which keeps a hash. Not logged. | True. |
| What you pasted into "read a booking" | `parse-booking` sends it to Claude and returns fields. It stores no text and no file. The app saves only the fields you tick. | True: pasted text is not kept. |
| The booking file | **Not true.** If you attach a file, the app uploads the original to the `docs` bucket and links it to every booking made from it. | Saved, private, trip members only. |
| AI prompts and answers | `ai_calls` has no content columns. `translate` stores nothing. | True for the log. **But** `place_lookups` keeps what you typed or linked, and the result. |
| Translator history | Kept only in this phone's storage (`translator-turns`), cleared on sign-out. | True. |
| Photo location (EXIF) | Privacy page says re-saving drops it. Not checked in code. | Unverified. |

**Saved, and an owner may not expect it**
- Original booking files in `docs`, including passports and tickets, kept as long as the trip exists. They also go to Anthropic (US) when read.
- Report text and phone type, readable by every member of the trip.
- Events carry a device id and, once signed in, the user id. Error text can include screen text (the privacy page says "never what you type").
- `place_lookups` keeps typed names and links, forever.
- Backups in `backups.*` hold real bookings and expenses.
- Share links stay readable by anyone with the link until stopped.

**On the phone (not on our servers)**
- Browser storage: offline copy of trip rows (`cache:*`), unsent changes (`outbox`, per account), device id (`vid`), settings, theme, language, guest answers before sign-up, translator turns, dismissed hints.
- Cache Storage: booking documents (`docs`, cleared at sign-out), place photos, map tiles.
- iOS widget: the App Group holds trip name, language, today's and tomorrow's stops (48 characters each), city, dates. No ids, members, money or notes (`widgetSnapshot.ts`). Cleared when the trip screen closes. Not checked on a device.
- Sign-out clears the offline copy and documents. It leaves the device id, the counting switch and other accounts' unsent changes.

## 8. Gaps, ranked

**A. Before open sign-up**
1. **No delete account, no leave trip.** Apple requires deletion in the app. Today, deleting a user by hand also fails if they paid an expense (`expenses.paid_by` has a foreign key with no action; the delete-account SQL drops it). Credits, share links and booking files would stay. Owner decision pending: apply after the trip or earlier (handoff section 4). Order: delete-account SQL, deploy the function, then `leave_trip`.
2. **Booking files with passport numbers.** Check the `docs` bucket rules as a normal user (they are not in the repo). Apply the file-type limit. Set a bucket size limit. Decide a rule for orphans after trip deletion.
3. **Test data in front of real users.** 373 users include the stress-test accounts (21, `toogo.stress.uNN@example.com`, 6 trips, each with 240 to 500 copied cards) and the "Load 99" and `test_trips` data. The cleanup script is in the session scratchpad, not the repo. Clean before launch so numbers mean something.
4. **Per-user limits.** Exists: AI daily caps per person and all, credits, 5 trips per hour (if applied), 20 pending photos, event rate per device id. Missing: total trips per user, members per trip, rows per trip, files per trip, bucket size. `track` is open to signed-out callers and the limit is per device id that the caller picks, so the events table can be flooded. Add a global per-hour cap.
5. **Bot accounts.** With "Confirm email" on, unconfirmed rows stay in `auth.users`. Plan a cleanup. Needs SMTP first (`docs/email-setup-2026-11-16.md`).

**B. Soon after**
6. **Retention.** One scheduled cleanup, written like `events_cleanup`. Suggested starting points (owner to decide): `ai_usage` and `join_attempts` 30 days (check the daily cap only looks back one day), `ai_calls` 12 months and clear the user id after 90 days, `place_lookups` 90 days, `push_subscriptions` marked off 90 days, `reports` 2 years (the privacy page promises it). Confirm the events cleanup is applied. It runs by chance in 1 of 200 calls and costs time inside `track`; a scheduled run is better.
7. **Backups.** After the trip: drop `backups.*` and `places_area_backup_20261108`. Before that, check the `backups` schema is not exposed in the API and has no grants to `anon` or `authenticated`.
8. **RLS check.** Run `select relname from pg_class c join pg_namespace n on n.oid = c.relnamespace where n.nspname='public' and c.relkind='r' and not c.relrowsecurity;`. Expect nothing. The repo shows RLS on for every table; `test_trips` is not in the repo. Tables with RLS on and no policy (server only, by design): `ai_calls`, `ai_usage`, `geo_cache`, `join_attempts`, `credit_unlimited_trips`, `app_admins`, `push_subscriptions`, `notifications_sent`, `trip_place_uses`, `library_interest(_base)`. Also the baseline shows `anon` and `authenticated` with table rights DELETE and TRUNCATE on `trips`; RLS blocks them, but revoke them anyway. Nothing was tested as a normal user (read review only).
9. **Leaver data.** `plan_state`, trip credit rows and share links have no link to the trip row; they stay after a trip is removed unless the built function or `leave_trip` removes them.

**C. Privacy page against reality** (`scripts/pages/privacy.mjs`)
- "Problem reports: up to 2 years": nothing deletes them.
- "It never includes what you type": error events keep 200 characters of the message. The legal agent's fix is not applied.
- "Usage counting already sent stays without your account attached": the device id stays on the rows.
- "Delete by writing to us, within 30 days": works only by hand and can fail on a user who paid an expense, until the built delete is applied.
- "Places stay without your name": true, but `place_library.added_from_trip` points to a trip.
- "Booking documents: private, trip members only": true if the `docs` rules are as intended. Not checked.
- "We keep AI calls without content": true. The page gives no AI-log retention period, and there is none.
- Photos re-saved without location: not checked in code.

Storage buckets
- `card-photos`: public read. Written by edge functions with the service key. Approved user photos go to `submitted/<id>.jpg`.
- `docs`: private. Path `<trip id>/<uuid>.<ext>`. Access rules not in the repo. Signed links last 10 minutes.
- `photo-submissions`: private, JPEG only, 6 MB, 20 pending per user. Path `<trip id>/<user id>/<uuid>.jpg`. Reader: owner or admin.

Edge functions that write: `suggest-place` (`place_lookups`, `ai_calls`, `ai_usage`, library), `parse-booking` (`ai_calls`, `ai_usage`, credits; no content), `translate` (same, no content), `card-facts` and `card-photos` (cards, library, photos, photo_submissions), `review-photo` (admin only), `notify` (`notifications_sent`, `push_subscriptions`), `sign-up` (auth user, invite check), `plan-trip` (plan rows; sends place names to OpenStreetMap).
