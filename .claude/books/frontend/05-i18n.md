Hebrew is the key; English sits in `src/i18n/`. Rule 1 in `toogo-rules`: every new or changed Hebrew text gets its English in the same change, and the layout is checked mirrored.

## How it works (`src/i18n.ts`)
- `t('עברית', {name})` returns the Hebrew itself, or in English `EN[he]`; `{name}` placeholders fill from vars. A missing English entry silently shows Hebrew.
- `lang` / `isEn` / `locale` ('he-IL' or 'en-GB') are read once at load from `localStorage.lang`. `setLang` writes it and reloads, so module-level `t()` calls (like `TABS` in App.tsx) are right. Never call `t()` at module level for text that depends on a runtime choice other than language.
- `index.html` sets `<html lang dir>` before first paint; `?lang=en|he` in the URL overrides and is saved.

## English files (`src/i18n/en.ts` merges them)
`en-a` shell/home/more/lists; `en-b` plan/places/add/swipe; `en-c` bookings/money/essentials/baby/translator; `en-shared` city names; `en-money`, `en-ux`, `en-plan2`, `en-redesign`, `en-safety`, `en-fixc` later additions. Add to the file for your area; keys must be unique across files (later spreads win).

## The check
`node scripts/i18n-check.mjs` (add `--list`): bundles `en.ts`, finds every `t('...')` key without English, and Hebrew text outside `t()`. Exit 1 on any. A line that is Hebrew on purpose carries `// he-only`. Run it in every UI change (`toogo-ship-check`).

## Mirror (LTR)
`src/styles/ltr.css`: `html[dir='ltr']` rules for what was set for RTL by hand. Use `.flip-ltr` on arrows that point "forward" in Hebrew. Prefer logical CSS (`margin-inline-start`, `inset-inline`). Known misses: not-now and undo icons point the wrong way in Hebrew, English arrows in `QuickFab`, names glued to prepositions ("לYuki").

## Display helpers
`keepRanges(s)` isolates number ranges (`¥500–1,000`) so RTL does not reverse them; display only, never saved. Dates use `locale`; Stays `shortDate` still uses browser locale (QA).

Legal wording: the English photo-licence line differs in meaning from the Hebrew ("for good" vs "forever", en-c.ts) and is flagged in the QA report.

Related: `.claude/books/ux` RTL page.

## Craft rules (`toogo-frontend-craft` "Mixed Hebrew and English", `toogo-ux-ui-craft` "Type rules")
- **`<bdi>` around English or Japanese names in Hebrew lines.** Done in 13 view files (AddPlace, Swipe, Itinerary, Bookings, Places, Expenses, ...). Not done where a name goes through `t('... {name}')` into a toast or label: `Itinerary.tsx` `say(t('הסרנו: {name}'))`, `MatchPop.tsx` names, `Stays.tsx` `{city}`. The `{name}` fill in `t()` is plain text; either wrap at the JSX site or add Unicode isolates (U+2068/U+2069) in `t()` vars (one change in `src/i18n.ts`, owner decides).
- **No added letter-spacing on Hebrew.** The global headings use negative tracking (`styles.css` h2, h3, `.large-title`, `.big`, `.card-title h2`; `plan.css`, `info.css`, `onboard.css`). Hebrew has no case and tracking breaks joined shapes. Rule wins: add `html:lang(he) :is(...) { letter-spacing: 0 }` once in `ltr.css`-style, or set tracking only under `html[lang='en']`. `.code` and `.bk-code` are Latin codes and may keep theirs.
- **Strings stay whole:** never build a sentence from two `t()` pieces; names glued to prepositions ("לYuki") stay a known miss.
- **Locale:** `Stays.tsx` `shortDate` passes `undefined` as locale; use `locale` from `i18n.ts`.
- **Raw error text** must not reach `t('שגיאה: {msg}', ...)`: that pattern puts English server text inside a Hebrew line. Use one plain string per failure (rule 1: with English).
