**Buckets**
- `card-photos`: public. Place photos found by card-photos or approved by an admin. Objects are only written by edge functions (service role).
- `photo-submissions`: private, jpeg only, 6 MB. A trip member uploads to `<trip id>/<own user id>/<uuid>.jpg` (policy checks `is_trip_member` and that the second folder is the caller). The caller and admins can read; the caller can delete. The `photo_submissions` insert policy needs pending status, the same path pattern, a card of that trip, and fewer than 20 pending. Nothing waiting is public. `review-photo` re-checks the path pattern before touching storage.
- booking documents: PDFs and photos, policies scoped to trip members (verified live 16 Nov). The policies are NOT in the repo (only a copy in a backup schema), `2026-11-01-docs-bucket-types.sql` (type limit) is unknown/not applied. QA open: `bookings.file_path` accepts any string; files are not cleaned when a trip is deleted; file extension comes from the file name; no client size check.
- Open: approved user photos keep GPS (EXIF) when published.

**Push (web push only; `features.push` on, per HANDOFF)**
- Tables `push_subscriptions`, `notifications_sent` (2026-11-14-push.sql). RPC `push_subscribe` validates shape (https endpoint, key lengths) but accepts any https host; `push_unsubscribe` only marks the caller's row off.
- `notify` checks membership, a real like and a real match, 40 an hour, once per person. VAPID keys are function secrets, generated by `scripts/push-keys.mjs`; never commit them.
- Open: restrict endpoints to real push services (FCM, Mozilla, Apple web push); add a timeout in `sendPush` (`_shared/webpush.ts`); sign-out leaves the phone subscribed to the old account (next user would see the old account's matches on the lock screen); lock screen shows names and place; no `pushsubscriptionchange` handler; failed pushes not retried.
- The App Store app has no web push; Apple push needs the paid developer licence.
